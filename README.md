# Flight Delay Predictor

Final-year undergraduate research project: comparing tree-based machine learning ensembles (Random Forest, XGBoost) against an attention-based deep learning model (FT-Transformer) for predicting US flight departure delays from 2018–2019 BTS flight data combined with Open-Meteo hourly weather.

A lightweight Streamlit dashboard wraps the best-performing model for a proof-of-concept demonstration of operational deployment.

## Not included in the repo

The following are excluded for size reasons. Setup instructions below explain how to obtain them.

- **Trained models** (`Models/`) — hosted externally (see "Setup" below)
- **Raw BTS parquets** (`Data/Combined_Flights_201?.parquet`) — public, downloadable from the BTS Kaggle dataset
- **Weather cache** (`Data/weather_cache/`) — regenerated by Notebook 1 via the Open-Meteo API

## Setup

```bash
# 1. Clone the repo and enter it
git clone https://github.com/<your-username>/flight-delay-predictor-6.git
cd flight-delay-predictor-6

# 2. Create and activate a virtual environment
python -m venv venv
# Windows:
venv\Scripts\activate
# macOS / Linux:
source venv/bin/activate

# 3. Install dependencies
pip install -r requirements.txt
```

## Running the dashboard

From the project root:

```bash
streamlit run app/streamlit_app.py
```

The dashboard opens at http://localhost:8501. Pick an airline / route / time / weather preset and the FT-Transformer returns a delay probability and verdict.

## Re-running the research pipeline

The notebooks should be run in order. Notebooks 4 and 5 were originally executed on Google Colab with GPU access — paths inside those notebooks reference Google Drive and will need adjusting for local execution.

| Notebook | Purpose |
|---|---|
| 01 | Loads BTS parquets, fetches Open-Meteo weather, samples 300k flights, writes `01_cleaned_data.csv` |
| 02 | EDA, drives feature engineering decisions |
| 03 | Engineers the 31-feature representation, writes splits |
| 04 | Trains RF, XGBoost, and FT-Transformer; tunes thresholds on validation |
| 05 | Locked test-set evaluation, generalisation gap, permutation importance |
